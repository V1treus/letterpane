# Reporting a vulnerability

Do not put credentials, private mail, live exploitation details or sensitive profile files in public issues.

Use **Security → Advisories → Report a vulnerability** when GitHub private vulnerability reporting is available. Describe the affected version, impact and steps to reproduce using fictional accounts.

If that option is unavailable, use an issue to request a private contact. Keep vulnerability details in the private report.

The current 1.3.x builds are previews. There is no guaranteed response time, bug bounty or established long-term support policy. Build checks and dependency advisory checks do not constitute an independent security audit.

## По-русски

Уязвимости передавайте через **Security → Advisories → Report a vulnerability**, если кнопка доступна. Иначе запросите приватный контакт в Issues. Укажите версию и шаги с вымышленными ящиками в приватном сообщении.

## Українською

Повідомляйте про вразливості через **Security → Advisories → Report a vulnerability**, якщо кнопка доступна. Інакше попросіть приватний контакт в Issues. Зазначте версію та кроки з вигаданими скриньками у приватному повідомленні.
