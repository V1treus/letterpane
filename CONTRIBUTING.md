# Работа с исходниками

Для тестов нужен Windows x64 с Node.js 22+; для релизной сборки — точная версия из .node-version (сейчас 24.21.0) и .NET Framework 4.8. Сборщик сверяет Node.js с официальным SHA-256. При первом запуске нужен доступ к официальному NuGet для закреплённого SDK WebView2.

1. Установите зависимости: `npm ci --ignore-scripts`.
2. Проверьте синтаксис и тесты: `npm run check`, `npm test`.
3. Соберите окно: `npm run build`.
4. Проверьте интерфейс на вымышленных данных: `npm run demo`.
5. Соберите один EXE: `npm run build:single`.
6. Для проверки двух поставок создайте также ZIP: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Zip`, затем `npm run verify:release` и `npm run smoke:release`.

Перед добавлением файлов в Git выполните `npm run check:source`. Проверка рассматривает отслеживаемые и новые неигнорируемые файлы, блокирует профили и некоторые известные форматы секретов; совпавшие значения не выводятся. Это дополнительная проверка, а не доказательство отсутствия всех секретов.

Workflow `.github/workflows/windows.yml` выполняет эти действия на windows-2022 и windows-2025. Он не публикует релиз: сохраняет только проверенные EXE, ZIP и SHA256SUMS как временные артефакты Actions. Реальные аккаунты и секреты CI не нужны. Изменения workflow проверяйте по [официальной документации GitHub](https://docs.github.com/en/actions/reference/security/secure-use); actions закрепляются по полным SHA.

Версия задаётся в package.json и package-lock.json. Нативные сведения о версии генерируются в `.build/AssemblyInfo.cs`. `build-info.json` содержит версии компонентов, commit (если существует) и признак изменений исходников, без путей профиля. Манифест файлов и хеши не заменяют подпись издателя. Подробный ручной прогон — [docs/TESTING.md](docs/TESTING.md).

Тесты не требуют почтовых аккаунтов. Проверка DPAPI выполняется под текущим пользователем Windows. Установка зависимостей, сборка и проверка демонстрации не должны требовать настоящих refresh-токенов.

## Изменения интерфейса

Палитры находятся в public/themes.css, компоненты — в public/style.css, настройки внешнего вида — в public/customize.js. Следуйте DESIGN.md. Проверяйте светлую и тёмную темы, крупный текст, клавиатуру, узкое окно и 500 демонстрационных ящиков. Для изменений геометрии проверяйте все три режима чтения.

## Ошибки

Укажите версию Letterpane, версию Windows, воспроизводимые шаги и ожидаемый результат. По возможности воспроизведите проблему в деморежиме. Не прикладывайте токены, полный импорт, хранилище профиля или личные письма. Скриншоты для документации делайте на демоданных.

Пользовательские профили, временные файлы, зависимости и готовые сборки исключены из Git. Перед публикацией проверьте состав добавленных файлов. Готовый EXE распространяется отдельно от профиля.

## Переводы / Translations / Переклади

Каталоги находятся в `shared/locales/ru.mjs`, `en.mjs` и `uk.mjs`. В каждом должны быть одинаковые ключи и параметры `{name}`. Для количества используйте формы `Intl.PluralRules`: `one/other` для английского, `one/few/many/other` для русского и украинского. Не соединяйте переведённые фрагменты в предложение: добавьте полную фразу с параметрами.

В HTML переводите только явно размеченные `data-i18n` и `data-i18n-attrs`; в коде интерфейса используйте `t(key, values)`. Ошибки и журнал должны хранить `message(key, values)`, чтобы их можно было показать после смены языка. Не переводите письма, адреса, пользовательские названия, группы и заметки.

Ключи `native.*` используются и в окне Windows. Сборщик создаёт `.build/NativeCatalog.cs` из общих каталогов; этот файл не редактируется и не добавляется в Git. После перевода пересоберите приложение, проверьте смену языка, отмену и повторный запуск. Все языковые ресурсы включаются в EXE; онлайн-переводчик не используется.

## Проверки интерфейса

Браузерные инструменты находятся отдельно в `qa/` и не входят в переносную сборку. Для первого запуска выполните `npm --prefix qa ci --ignore-scripts`, затем `npm --prefix qa run browsers` и `npm run test:ui`. Скриншоты и трассы ошибок сохраняются в `.build/ui-test-results`, который исключён из Git.

Можно использовать установленный Chrome, указав только для тестового процесса `POSTA_QA_CHROME` с путём к chrome.exe. Playwright создаёт отдельный временный контекст; обычный профиль браузера не используется. На CI устанавливается тестовый Chromium. Тесты запускают локальную службу с вымышленными данными и не начинают синхронизацию Microsoft. Они не заменяют проверку нативного окна WinForms/WebView2 и масштаба Windows.

Run `npm run check` and `npm test` after changing a translation. Keep the same keys and placeholders in all three catalogs. Use complete sentences with parameters and the appropriate plural forms. Check the native app as well as the web interface. Never translate mail content or user-entered account data.

Після зміни перекладу виконайте `npm run check` і `npm test`. Зберігайте однакові ключі й параметри в усіх каталогах. Використовуйте цілі речення та відповідні форми множини. Перевіряйте також вікна запуску. Вміст листів і дані користувача не перекладаються.
